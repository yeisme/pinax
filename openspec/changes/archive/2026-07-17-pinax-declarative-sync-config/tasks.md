- 第一版 unlock provider 为 `fake`（AES-GCM，`PINAX_SYNC_FAKE_KEY`）和 `env`（`PINAX_SYNC_SECRET_<IDENTITY>`）。生产 age/keychain provider 需独立依赖审计后注册；`doctor` 会标记 fake provider。这是 Open Question 1 的明确延后。

- tenant/app 命名空间当前只验证和展示为 namespace facts，不改变现有远端对象布局；完整 server-side RBAC/quota/audit 是独立 server control-plane capability。
- 该 capability 标记为 **experimental**；stable-from 评审需要真实 dogfood evidence（类似 agent-memory-runtime 的 closeout 路径）。
